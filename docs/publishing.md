# Publish to live

Editors publish in Contentstack. The public site updates itself a few minutes later, with no developer involved.

```
Contentstack publish ──webhook──▶ relay (AWS Lambda) ──▶ GitHub Actions "Deploy"
                                                          cms:pull → tests → build → scan → S3 → CloudFront
```

- **Why a relay?** Contentstack webhooks send their own JSON body. GitHub only starts a workflow when the request uses GitHub's format and carries a GitHub token. The relay checks the webhook's Basic Auth password, then calls GitHub. It forwards nothing from the webhook.
- **Timing.** A publish is usually live in 2–4 minutes. Deploys run one at a time. Publishes made during a deploy collapse into one follow-up run.
- **What the public site shows.** Only published content. Drafts and the instant result of an edit need Contentstack Live Preview, which this setup does not include.
- **Other triggers.** A push to `main` deploys code changes the same way. You can also start a deploy by hand from the repository's Actions tab.

## Pieces

| File | Role |
| --- | --- |
| `.github/workflows/deploy.yml` | Pulls published content, runs unit tests, and calls `npm run deploy:aws -- content` |
| `infra/publish.yaml` | GitHub deploy role (OIDC, no stored AWS keys) and the webhook relay. Generated by `npm run infra:publish-template` from `infra/publish-relay.js`. |
| `scripts/setup-publishing.sh` | One-time setup for AWS and GitHub |

The deploy role can only read the site stack's outputs, write objects in the site bucket, and invalidate its CloudFront distribution. Changing the infrastructure itself remains a manual `npm run deploy:aws` from a developer machine.

## Setup (once)

1. Deploy the site from your machine: `aws login`, then `npm run deploy:aws`.
2. Create a GitHub repository for this project and push `main`.
3. Create a fine-grained GitHub token, limited to that repository, with **Actions: Read and write** and nothing else. The relay uses it only to start the Deploy workflow; it cannot push code.
4. Fill `.env` with your Contentstack delivery settings (`CONTENTSTACK_API_KEY`, `CONTENTSTACK_DELIVERY_TOKEN`, `CONTENTSTACK_ENVIRONMENT`, `CONTENTSTACK_REGION`), then run:

   ```sh
   npm run setup:publishing -- OWNER/REPO
   ```

   The script deploys `infra/publish.yaml`, reusing your account's GitHub OIDC provider if one exists. It then creates the GitHub `production` environment (limited to `main`), stores the role ARN and Contentstack settings there, and prints the webhook details. The management token is never sent to GitHub.
5. In Contentstack, open **Settings → Webhooks → + New Webhook**:
   - **URL:** the printed webhook URL
   - **Authentication:** Basic Auth, username `contentstack`, the printed password
   - **Scope:** branch-level, branch `main`
   - **Trigger conditions:** Entry → Published, Unpublished and Deleted, in your delivery environment. Leave **Updated** off: it fires on every draft save, which doesn't change the public site.
6. Publish an entry. In GitHub's Actions tab, a Deploy run should start within seconds.

Rerunning setup is safe. It keeps the existing webhook password and GitHub token. To replace the token, set `GITHUB_RELAY_TOKEN` when you rerun.

## Security notes

- Pull requests never run the deploy workflow. Its secrets live in the `production` environment, which only `main` may use, and the AWS role trusts only jobs in that environment.
- The GitHub token and webhook password are stored as Lambda environment variables (encrypted at rest) and as `NoEcho` stack parameters. Anyone with Lambda read access in your AWS account can see them.
- The webhook URL is public. Without the password it returns 401 and starts nothing. With the password, the worst case is extra rebuilds.
- Rotating: rerun setup with `GITHUB_RELAY_TOKEN` for the token. For the password, update the `WebhookPassword` stack parameter and the Contentstack webhook.

## Cost

Lambda and its logs (kept 14 days) cost nothing noticeable at this volume. GitHub Actions minutes are free for public repositories. Each deploy also adds a CloudFront invalidation; the first 1,000 paths per month are free.

## Removal

```sh
aws cloudformation delete-stack --stack-name naturedex-contentstack-publishing --region us-east-1
```

Then delete the Contentstack webhook and the GitHub token. If the stack created the account's GitHub OIDC provider, deleting it also removes that provider.
